- (capability) CAP-1 intent: A developer can start a session from an HTTP/HTTPS Absolute URL and inspect its Full URL plus ordered Domain, Path Segments, and lossless Query Parameters. Success: supported input preserves duplicate keys, empty/absent values, encoded delimiters, IDN forms, untouched separators, and Fragment content without omission, merging, or silent reordering; unsupported input does not replace the session.
- (capability) CAP-2 intent: A developer can find and identify Managed Pieces across large URLs without changing URL state. Success: case-insensitive search covers Domain, Path Segments, Query Parameter keys and values, preserves source order and stable identity, reports no matches, and creates no History Entry.
- (capability) CAP-3 intent: A developer can precisely edit or remove Managed Pieces, add Query Parameters, and explicitly reorder Query Parameters while preserving unaffected URL content. Success: each accepted operation updates only its target, creates one History Entry, retains duplicate identity/order, and follows deterministic keyboard focus behavior.
- (capability) CAP-4 intent: A developer can edit the complete Full URL with trustworthy two-way synchronization while incomplete or invalid text remains an isolated Draft URL. Success: valid states atomically synchronize every representation; invalid Draft text is preserved while Structured View and Copy operate on Last Valid URL; structured mutations remain available against Last Valid URL and Full URL correction rebases on the latest committed snapshot.
- (capability) CAP-5 intent: A developer can reverse each committed URL mutation stepwise to the exact Initial URL. Success: visible Undo and the guarded platform shortcut restore exact serialized snapshots, synchronized pieces, stable identities, and deterministic focus; search, focus, selection, validation attempts, and raw keystrokes do not pollute product History.
- (capability) CAP-6 intent: A developer can copy the latest valid committed URL and understand mutation, validation, and copy outcomes without workflow interruption. Success: Copy never returns stale or invalid Draft content, clipboard failure exposes the exact source for manual copy, and visible/programmatic feedback neither falsely reports success nor steals focus outside explicit recovery.
- (constraint) All URL parsing, editing, search, History, and Copy preparation remain browser-local; URL-bearing content cannot enter network requests, persistence, telemetry, logs, crash reports, or performance traces, and reload/close clears the session.
- (constraint) V1 accepts only complete HTTP/HTTPS Absolute URLs with a host; relative URLs, domain-only input, and other schemes cannot start or replace a session.
- (constraint) Committed state is atomic across Full URL, Structured View, History, and Copy source; invalid edits preserve Last Valid URL and exact restorable History.
- (constraint) URL representation is lossless for supported semantics: exact snapshots preserve serialization, query entries remain ordered and distinct, encoded structural delimiters stay data, and unrelated mutations cannot canonicalize untouched content.
- (constraint) The application must remain operable at 20,000 URL characters and at least 250 Query Parameters, targeting initial parse within 1 second and local interaction feedback within 100 ms on 4-core/8-GB reference hardware.
- (constraint) Release supports the latest two major Chrome, Firefox, Edge, and Safari versions and blocks on the browser/assistive-technology evidence defined by the UX and architecture companions.
- (constraint) The complete journey and failure states meet WCAG 2.2 AA; every action is keyboard-operable, required controls remain available at 320 CSS px and 400% zoom without page-level horizontal scrolling, and state cannot rely on color alone.
- (constraint) V1 is a static, responsive, desktop-first single-workbench web application with full-DOM rendering at the supported capacity; no backend or runtime environment behavior may alter URL semantics.
- (decision) Non-goals: accounts, authentication, saved or shared sessions, collaboration, cloud persistence, API-client behavior, requests, URL shortening, batch processing, bulk comparison, relative URLs, managed scheme or Fragment editing, Postman/Insomnia integration, mobile-optimized workflows, Redo, dark mode, and a separate icon language.
- (decision) Success signal: 5–8 representative developers complete paste, find, change, Undo, and Copy unassisted at least 90% of the time, with zero critical synchronization, Undo, or stale-Copy failures; capacity fixtures preserve every Managed Piece and exact state through all required operations.
- (decision) The PRD decision required is resolved by later UX and architecture authority: during an invalid Draft URL, Structured View mutations remain enabled against Last Valid URL while preserving Draft text exactly.
